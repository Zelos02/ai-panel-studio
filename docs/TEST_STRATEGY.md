# AI Panel Studio 测试策略

## 1. 原则

- 领域逻辑与真实模型、网络和系统时间解耦。
- TDD 优先覆盖状态转换、调度、句数限制、幂等和隔离等高风险规则。
- FakeLLMProvider 根据输入和调用序号返回确定结果，CI 不访问外部网络。
- E2E 使用临时 SQLite；每个用例独立 Seed，结束后清理。
- 测试失败必须保留可定位的请求 ID、sessionId 和事件序号，但不得输出 Key。

## 2. 测试层级

### 后端单元测试

- 实体与状态机合法/非法转换。
- TurnScheduler 非固定轮询、公平保护和候选选择。
- 发言 1～2 句校验、重写与安全截断。
- 模型 Schema 校验、有限重试、超时和取消。
- 知识分岔指纹、去重和来源约束。
- 上下文预算只读取当前 Session。

### 后端集成测试

- SQLite Repository、唯一约束、级联和事务回滚。
- Topic → Panel → Session API 主流程。
- 幂等键、重复 start、错误状态码。
- 事件落库顺序、SSE 回放、会话隔离与断线恢复。
- 错误响应不含堆栈、环境变量或模型原始载荷。

### 前端组件/集成测试

- 话题创建与字段校验。
- 阵容生成、重试、确认和锁定。
- Transcript 只显示公开内容，事件名不渲染。
- expert.status 只更新目标卡片。
- SSE 去重、重连、切换话题关闭旧连接。
- 自然语言总结渲染，结构化 JSON 不进入视图。
- 桌面/窄屏的关键布局与可访问性状态。

### E2E

- 完整演示路径。
- 模型超时/非法输出恢复。
- SSE 断线、重连、去重。
- 两个话题快速切换和并发运行隔离。
- 中途停止、运行中刷新、完成后只读恢复。

| 阶段 | 最低门禁 |

| Prompt 1 SDD | Mermaid 语法人工检查；需求均有映射 |
| Prompt 2 基础 | 后端配置/Repository/API 测试通过；前后端可启动 |
| Prompt 3 DDD | 组件测试通过；桌面/窄屏人工检查 |
| Prompt 4 入场 | API 与 UI 集成测试通过 |
| Prompt 5 编排 | 先见失败测试；核心领域覆盖关键分支 |
| Prompt 6 模型 | Mock 覆盖成功、非法、超时、取消、重试 |
| Prompt 7 SSE | 回放、去重、跨会话隔离测试通过 |
| Prompt 8 闭环 | 分岔、总结和恢复测试通过 |
| Prompt 9 E2E | 主流程与指定异常流程全部通过 |
| Prompt 10 交付 | 从空环境按 README 复现；密钥扫描无发现 |

## 5. 测试数据与可重复性

- 固定随机种子和可注入时钟。
- Fake Provider 依据 `topicId/sessionId/callIndex` 产生稳定响应。
- 任何测试不得依赖用例执行顺序。
- E2E 运行时设置较短但明确的最大轮次，避免时间型不稳定。
- 不用 sleep 猜测事件完成；等待具体 UI 状态或事件序号。

## 6. 发布前检查

1. 后端、前端、E2E 测试全部通过。
2. 浏览器控制台无未处理异常。
3. `.env`、构建产物、日志、Fixture 中无真实 Key。
4. Transcript 快照中无 `raise_hand`、urgency、Prompt 或 chain-of-thought 字段。
5. 总结视图不包含 JSON 包装。
6. 两个并发 Session 的事件序列与数据查询完全隔离。

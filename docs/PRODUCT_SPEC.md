# AI Panel Studio 产品规格（MVP）

## 1. 产品目标

AI Panel Studio 是一个可本地运行的 AI 圆桌讨论 Web App。用户输入讨论主题并选择专家人数后，系统生成一名主持人和一组立场有差异的虚拟专家；用户确认阵容后进入演播厅，观看主持人引导、专家自主举手/补充/反驳、知识分岔实时形成，最后获得可复盘的自然语言总结。

核心价值不是“多个聊天气泡”，而是让用户在几分钟内看到同一问题的多角度碰撞、论据推进、分歧与共识。

## 2. 目标用户

| 用户 | 任务 | 核心收益 |
| --- | --- | --- |
| 知识工作者/研究人员 | 快速多角度审视问题 | 获得不同视角、争议与摘要 |
| 产品/决策人员 | 在评审前预演立场和质疑 | 暴露盲点、检验假设 |
| 教育/内容创作者 | 将复杂主题结构化呈现 | 获得可回放的虚拟专家访谈素材 |

## 3. MVP 范围

### 3.1 用户主流程

1. 用户进入首页，浏览已有话题或创建新话题。
2. 用户填写主题、可选背景/目标和专家人数（默认 4）。
3. 系统生成主持人与专家阵容，显示姓名、职业/Title、立场、简介和颜色。
4. 用户可重新生成，确认后阵容锁定并进入演播厅。
5. 用户启动讨论；主持人开场，专家依据最新 Transcript 自主决定是否发言。
6. UI 实时追加 Transcript、专家公开状态和知识分岔。
7. 用户可停止讨论，或由主持人在满足结束条件后收尾。
8. 系统生成自然语言总结；用户可返回首页并重新打开记录。

### 3.2 功能需求

| ID | 要求 | 验收摘要 |
| --- | --- | --- |
| FR-001 | 话题管理 | 可创建、列表、查看并恢复多个话题 |
| FR-002 | 阵容生成 | 默认 4 位专家；生成主持人和专家完整资料 |
| FR-003 | 确认入场 | 未确认不能创建/启动讨论；确认后阵容锁定 |
| FR-004 | 主持人编排 | 主持人负责开场、提问、追问、串联与结束 |
| FR-005 | 自主发言 | 专家依据最新上下文返回 wait/举手/补充/反驳/发言，不按固定轮询 |
| FR-006 | 短发言 | 每条面向用户的发言为 1～2 句话 |
| FR-007 | 专家状态 | 独立显示等待、准备、发言中和公开关注点摘要 |
| FR-008 | 实时 Transcript | 发言逐条出现，仅展示发言人资料和自然语言正文 |
| FR-009 | 知识分岔 | 讨论过程中实时产生新概念、假设、冲突、待验证问题和延伸方向 |
| FR-010 | 自然语言总结 | 结束后展示焦点、观点、分歧、共识、未决问题和下一步，不展示 JSON |
| FR-011 | 会话隔离 | 不同话题/场次的上下文、状态、事件和产物不串线 |
| FR-012 | 断线恢复 | SSE 重连后按事件 ID 补发，前端去重 |
| FR-013 | Fake 模式 | 无真实 API Key 时可稳定演示与测试 |
| FR-014 | 错误恢复 | 模型超时、非法输出、断流等有中文提示、有限重试和安全降级 |

### 3.3 非功能需求

| ID | 要求 | 标准 |
| --- | --- | --- |
| NFR-001 | 安全 | Key 只由后端环境读取；不进入前端、数据库、日志或 Git |
| NFR-002 | 响应式 | 普通桌面紧凑分栏；窄屏无横向溢出，主要区域可独立访问 |
| NFR-003 | 可访问性 | 键盘可用、语义标签、状态提示、合理对比度、尊重 reduced-motion |
| NFR-004 | 可测试性 | 核心逻辑不依赖真实网络；Fake Provider 输出确定 |
| NFR-005 | 可恢复性 | 页面刷新可从持久化状态恢复；重复事件不产生重复消息 |
| NFR-006 | 可维护性 | 领域编排、模型适配、存储、HTTP/SSE 与 UI 分层 |
| NFR-007 | 可观测性 | 请求 ID、会话 ID、耗时和错误类别可追踪，敏感信息不落日志 |

## 4. 关键业务规则

1. 专家数量 MVP 允许 2～8 人，默认 4 人。
2. 一个话题可有多场 PanelSession，但同一时间最多一场处于 `running`。
3. 只有已确认（admitted）的阵容可以创建讨论场次。
4. 可见发言在保存前必须通过 1～2 句话校验；超限优先要求模型重写，失败时安全截断。
5. 编排器可以用“最近未发言时长”防止饥饿，但不能把它实现为固定轮询。
6. 专家内部行动决策、紧迫度和调度事件不可进入 Transcript。
7. UI 只显示模型给出的简短公开关注点摘要，不请求、存储或展示隐藏思维链。
8. 总结的结构化数据可以在后端内部使用，但前端只能收到或渲染自然语言字段。
9. Topic ID 与 Session ID 必须同时参与订阅校验，防止跨话题事件泄漏。

## 5. 页面与信息架构

### 首页

- 话题列表：标题、状态、专家数量、最近更新时间、摘要预览。
- 新建话题：标题、背景、目标、专家人数。
- 可继续未完成讨论或只读查看已完成讨论。

### 阵容确认

- 主持人与专家卡片。
- 重新生成、错误重试、确认入场。
- 确认后展示锁定提示。

### 演播厅

- Transcript 主舞台。
- 每位专家的状态窗口。
- 实时知识分岔面板。
- 连接状态、启动/停止控制。
- 结束后的自然语言总结。

桌面端各区域独立滚动；窄屏用分区 Tab/抽屉或自然堆叠保持可读性。

## 6. 明确不纳入 MVP

- 用户账号、组织权限、支付和云端多租户。
- 音视频、语音合成、真实人物仿真。
- 用户编辑模型隐藏推理。
- 基于知识分岔自动创建无限子讨论。
- 生产级分布式任务队列和跨机器扩展。

## 7. 完成定义

- 主流程与异常流程均有自动化测试。
- Fake Provider 下可以从零完成整场讨论。
- 至少 5 个高质量预设话题及对应阵容可通过 Seed 生成。
- README、ER 图、API 契约、Prompt 记录、开发工作流和测试证据齐全。
- 新环境按 README 可启动前后端并完成演示。
